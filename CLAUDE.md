# CLAUDE.md

**Roost** is a self-hosted, encrypted at rest (true end-to-end planned), MIT-licensed AI agent platform where each bot gets its own computer — its own Brave window and its own workspace container.

- Encryption wording: Roost is encrypted at rest. The server holds the key, so it is not end-to-end, and no new text (docs, UI, commit messages) may call it "E2E" or "zero-knowledge". The user wants real end-to-end encryption designed properly later, and the research has been requested.

## Architecture (Night-1 slice)

Gateway (FastAPI, `127.0.0.1:18800`) ← bots/talk/events → a per-bot Desk facade → the keeper process (`127.0.0.1:18801`, signed requests) → that bot's own Brave window + workspace container. Every message is a durable work item (`roost/work/`, one drain loop per bot in `roost/talk/runner.py`); bots hand work to each other with `ask_bot` (a `handoff` item in the target's queue) and talk together in rooms (`roost/rooms/`). Schema changes are versioned, additive migrations in `roost/db/migrations.py` (`PRAGMA user_version`); `schema.sql` is the frozen v0 baseline.

Every bot gets every tool (S1, Ruling 28): web, tasks, money, notes, documents, `ask_bot` and `list_bots`, each with a gate kind (`read` / `write_create` / `write_change`). `bot_roles` stays in the database and is read by nothing. Templates (`roost/bots/templates.py`) only fill the New bot form. The main bot exists from the start (`roost/bots/main_bot.py`). Only it may `create_bot`, in a 1:1 run started by your own message. Owner decision (2026-10-29, "don't restrict me, use Fable to detect injections"): when that run has read web content, the gate's `checked_create` verdict has the create check (`roost/create_check/`) ask the main bot's own model whether the bot's name, job and whole instructions fit your newest own messages; only an exact `fits` creates it, and its card says "Auto-checked". Anything else is the old refusal, and the main bot shows a suggestion card instead. Your Yes on a create card counts as the check. Your own chat (owner, 2026-11-03, "the bot just does what you ask", `roost/talk/owner_chat.py`): in a 1:1 run of your own chat that can show a card, a change to your records (`OWNER_CHAT_RECORD_TOOLS`), `remember`, `set_bot_model`, `update_my_instructions` and the direct routine tools are judged by the approval mode as in a clean run even after web content (reason `owner_chat_change`, no model check); routines, handoffs, rooms and helpers keep D3's refusal. In that chat `open_page` opens any `askable_url` with no Open card and a click to another site runs (`owner_site`), widening the fence. Only paying asks there (owner, 2026-11-05, "like Grok"; reason `owner_chat_act`): a send, submit, accept, delete or account click runs, typing a secret that is your own words (an ID number you gave) runs (a made-up contact detail still asks), and the bot's programs run after web content; a spend or a button Roost can't read keeps the reviewer or its card, a password box stays never, and routines, handoffs and rooms keep the hard floor. New bots start in Auto-edit with auto-review on (existing bots keep their stored mode: migrations are additive). A bot's computer has screenshots and an in-memory control lock (`roost/desk/control.py`).

A bot that meets a human check or a code check stops cleanly (owner, 2026-11-03: a sign-in page no longer does; its result carries a sign-in note, the bot signs in itself, and only `ask_secret_field` or `request_sign_in` opens the card) (the stuck flow, `docs/plans/2026-10-14-roost-stuck-flow-design.md` §6): the pure detector (`roost/desk/stuck.py`) or the bot's own `ask_for_help` raises a block, and in a run of your own chat messages the run ends with a Stuck card (`roost/stuck/`, schema v12 `stuck_cards`) while the bot shows Stuck; handoffs, rooms and routines get a loud `Blocked:` tool result instead. The card's Give it back / Try again (`POST /api/stuck/{id}/clear`) posts your continue line and queues a `card_answer` item that carries the task on, Give up ends it, and "Use my main Brave" only has the keeper run `/usr/bin/open -a "Brave Browser" <url>` (no shell, no automation, no debug port, no profile access). Like Grok (owner, 2026-11-02), your own message in the card's chat, or a reply quote of the card (its quiet Reply on web and phone), answers it instead (`roost/stuck/typed_reply.py`): the card closes as `replied` (schema v38 `stuck_cards.replied`, shown as "You answered in the chat"), control is given back, the status settles, and the run your message starts gets one trusted line naming the host and the reason in fixed words (the request only from an untainted card) and telling the bot to carry on if you said the block is cleared, or to do your new task instead.

Notes and documents are the **user's** too (`roost/notes/`, `roost/documents/`): one encrypted blob per document (AAD `docs:payload` / `sheets:payload` / `pdf:payload`), a `revision` compare-and-swap on every save (409 + the current copy), and the web editors are lazy chunks built from Univer's open-source presets only (`web/tests/licenseGate.test.ts`).

A project (the `money_projects` table, schema v13) holds its tasks, money, notes and documents. `roost/projects/numbers.py` is the one place for the sums: the total and monthly budgets, bar tones, other currencies, and each task's planned / spent / left. `ProjectService` (`roost/projects/service.py`) owns create, update, archive, top-ups and delete; a deleted project's expenses move to the hidden General project, and its tasks, notes and documents are unlinked. Every bot has the project tools. The Board's first tab, Projects, opens a page per project at `/board/projects/:projectId`.

The web's look (redesign P1): `web/src/styles/tokens.css` is the one place for colours, font sizes and the other design values (`web/tests/tokens.test.ts` refuses a hard-coded colour or font size anywhere else and keeps every text colour at 4.5:1), and `web/src/ui/` is the kit every screen builds from: buttons and fields, Radix Select, Menu, Tabs, Sheet, Popover and Tooltip, Toast, and the DatePicker and DateTimePicker, whose calendar is a lazy chunk and whose days and times are Madrid's (typed words are read by `GET /api/dates/parse`). Every bot is a robot (`web/src/components/robot/`): one of six heads in its colour, with a screen in one of three styles that shows its status; old bird shapes still draw, through one table in `look.ts`. A picture the user uploads (`/api/bots/{id}/picture`) shows on the robot's screen and is stored sealed in the avatar JSON.

The chat (redesign P2): a bot's reply renders as markdown through `web/src/components/markdown/Markdown.tsx`, the one module that imports react-markdown, a lazy chunk the notes preview shares: no raw HTML, a link shows its real host, an image is never fetched, a `[[wikilink]]` is a chip, and the plain text shows while it loads or if it never does. `web/src/components/chat/` holds a message's pieces: copy and time on hover, the "from web content" mark, typing dots while a bot is On it with no text yet, a caret while text streams, and the bot's steps as compact lines ("Added a task"), built from live `bot_status` activities (`toolLines` in `store/live.ts`, gone after a reload until P4's record cards). The composers grow with their text in every browser, and the chat keeps its last message in view. Home lists the main bot first, wearing its star, with unread dots this browser remembers (`web/src/lib/unread.ts`).

The shell (polish R1): the sidebar (`web/src/components/sidebar/`, sorted by `web/src/lib/sidebar.ts`) holds search and + on top, a row of your bots with the main bot first, then the chats under group headings (a bot's optional label, schema v16 `bots.group_label`, sealed under `bots:group_label`, set with `group` on `PATCH /api/bots/{id}`; never sent to a model), and your initials and Board at the bottom. C1 and C2 are built (a Linux computer per bot, the default; the live screen; Take control; Vault: site logins). C3, the computer-use loop, is built too (below).

Computer use (C3, `docs/plans/2026-10-22-roost-computers-c3.md`, no migration): a bot on its Linux computer gets six screen tools (`roost/computer_use/tool_specs.py`: `look`, `wait_ready`, `scroll` read; `click`, `type`, `press_key` are the gate kind `act`). `look` brings Chromium's window up and returns a masked viewport JPEG (field boxes painted grey) and an escaped `<untrusted_page>` summary of the URL, readiness, controls and page text; the image goes to the model only (`ModelRequest.images`, the newest look's alone), never to storage, a log or the web. Routines and Plan (`docs/plans/2026-10-22-roost-routines-plan.md`, schema v25): a routine (`roost/routines/`, `routines`, `routine_runs`) is a name, instructions and Madrid times (a weekday list with times, or a cron line no more often than every 15 minutes), with a switch, Run now, History and an editor on the Info tab. Hardening: the Claude SDK is pinned at `claude-agent-sdk==0.2.170` and its process env turns CLI telemetry and non-essential traffic off (`DISABLE_TELEMETRY`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`).
